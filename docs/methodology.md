# 研究方法

版本：1.0.0
適用範圍：臺北市萬華區社區發展協會資料層

## 1. 研究目的與分析單位

本專案建立可追溯、可重製且可逐步擴充的社區研究資料基礎，用於回答下列問題：

1. 萬華區有哪些社區發展協會，政府名冊提供哪些基本欄位？
2. 在證據充分時，協會有哪些活動、獎項、SDG 對應與資金紀錄？
3. 如何在不掩蓋缺值與不確定性的前提下，形成可比較的評估資料？

核心分析單位是「社區發展協會」。活動、獎項、SDG 評估、資金與 AI 評分均透過 `community_id` 關聯至同一社區。資料列的時間粒度依資料表而異，不把名冊刊載日期誤當成活動或營運狀態。

## 2. 資料來源

目前核心名冊來源為臺北市政府社會局「臺北市社區發展服務_社區發展協會」開放資料。原始來源快照、下載資訊、校驗碼及授權歸屬記錄於 `data/external/taipei-city/2026-03-31/`。

來源優先順序如下：

1. 政府開放資料、政府公告與法定公開紀錄；
2. 協會官方網站或官方社群公告；
3. 可識別作者、日期與方法的研究或機構資料；
4. 新聞與其他二手來源，只用於線索，不單獨支持高風險結論。

每筆非示例紀錄至少保存來源名稱、網址、存取日期、資料版本或更新時間。來源消失時保留既有稽核資訊並標記，不以未註明的替代來源覆寫。

## 3. 資料生命週期

| 階段 | 位置 | 原則 |
| --- | --- | --- |
| 外部原始資料 | `data/external/` | 原樣保存第三方下載，不在原檔上修正 |
| 第一手原始資料 | `data/raw/` | 原樣保存訪談、觀察或自行蒐集資料；本版未收錄 |
| 欄位結構 | `data/schema/` | JSON Schema 與關聯規則為欄位契約 |
| CSV 交換層 | `data/csv/` | 每列一個觀察單位、每欄一種資料型別 |
| JSON 發布層 | `data/json/` | 保留數字與布林型別，附資料集版本封套 |
| 處理後資料 | `data/processed/` | 通過驗證、可供分析或人工檢閱的衍生資料 |

空白欄位代表未知或不適用，不使用 `N/A`、`-` 或 `0` 作為不明值。日期統一為 ISO 8601，座標使用 WGS84，識別碼不得因名稱、行政區或年度變更而重用。

## 4. 蒐集、清理與關聯

1. 保存來源快照並計算校驗碼。
2. 驗證檔案編碼、欄名與筆數，保留來源欄位，不直接修補原始值。
3. 以行政區代碼 `63000070` 選取萬華區紀錄。
4. 建立穩定 `community_id`，名稱變更透過映射表處理，不重新編號。
5. 將民國日期轉為西元 ISO 日期，保留可追溯來源。
6. 將活動、獎項、SDG 與資金資料透過外鍵連回社區；活動層外鍵還必須屬於同一社區。
7. 產生 CSV、JSON 與處理後檔案，執行結構、型別、外鍵、日期區間與合理值檢查。

地址解析出的里別或座標屬於衍生欄位，必須記錄方法與來源。不能確認的值留空，不以推測補齊。

## 5. 證據層級

| 等級 | 定義 | 可支持的用途 |
| --- | --- | --- |
| A | 可下載政府資料、政府公報或具穩定識別碼的官方紀錄 | 核心事實、正式評分 |
| B | 協會官方公告或具日期的官方頁面 | 活動存在、組織自述；重要成果宜交叉驗證 |
| C | 可追溯的研究、機構或新聞二手資料 | 補充脈絡、待確認線索 |
| D | 未驗證輸入、教學資料或模型建議 | 不得作為研究結論或正式排名依據 |

來源之間衝突時不直接選擇較新或較完整者，而是保留衝突、記錄判定理由並降低資料品質或信心標記。

## 6. 範例資料政策

本資料層需要範例資料以測試欄位、關聯、排序與介面。為避免合成資料被誤認為事實：

- 合成紀錄使用 `EXAMPLE` 識別碼；
- `is_example=true`；
- `data_quality_flag=synthetic_example`；
- 內容與備註明示「教學示例」或「非真實」；
- 正式研究、圖表、排名及對外報告必須排除所有示例紀錄。

`CommunityProfile` 的三筆示例列採用既有政府名冊真實欄位，故標記為 `is_example=false`；其相關活動、獎項、SDG、資金與排名資料均為合成示例，兩者不得混為同一證據層級。

## 7. 品質保證

每次資料發布至少檢查：

- 主鍵非空白且唯一；
- 外鍵可解析，且活動關聯的社區一致；
- 日期與期間先後順序正確；
- SDG 目標介於 1–17，信心值介於 0–1；
- 評分構面介於 0–100，加權總分可重算；
- 金額與人次不得為負值；
- CSV 與 JSON 筆數、欄位與值一致；
- 合成示例不會進入正式分析母體；
- 無公式錯誤、私人聯絡資料或未授權內容。

重要衍生結果須由第二位研究者或指定審核角色覆核。變更欄位意義、權重或資格規則時提升 schema 或模型版本並寫入 `CHANGELOG.md`。

## 8. 倫理、隱私與授權

即使來源公開，也僅保存研究目的必要的組織層級資料。公開衍生資料不保存負責人姓名、私人電話、私人電子郵件或可避免的個人識別資訊。訪談或第一手資料在進入 `data/raw/` 前需有同意、保存期限、去識別與存取控制方案。

政府資料依臺北市資料開放平台授權條款使用並保留歸屬。其他來源必須逐筆確認引用與再利用權限。

## 9. 限制

- 名冊列入不等於協會目前仍在營運。
- 政府名冊未提供活動、補助、獎項或 SDG 成效，不能由缺席欄位推論「沒有」。
- 地址座標是組織地址位置，不代表活動服務範圍。
- 公開資料量較多的協會可能產生可見度偏誤，因此評分需另行處理證據充分度。
- AI 只能協助抽取、分類與初步建議，不能取代來源核對與人工審核。

## 10. 更新與重製

建議每季檢查政府資料版本，每年進行一次完整覆核；重大公告則事件驅動更新。所有正式輸出應可由已提交的來源快照、映射規則、schema 與評分版本重製。研究引用時應同時記錄資料版本、模型版本與存取日期。
